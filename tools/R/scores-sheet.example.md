## What each landscape is

- `all-extensive-arable` — Every hexagon extensive arable.
- `all-intensive-arable` — Every hexagon intensive arable. Expect the worst pollution numbers.
- `all-extensive-livestock` — Every hexagon extensive livestock.
- `all-intensive-livestock` — Every hexagon intensive livestock.
- `all-agropark` — Every hexagon agropark.
- `all-nature` — Every hexagon extra nature. No agriculture at all.
- `half-intensive-half-nature` — Alternating intensive arable and nature.
- `mostly-nature-some-farms` — 46 of 465 extensive arable, the rest nature — roughly what a cautious player builds.

## Two things to know before you read the table

**1. The rows ARE comparable with each other.** Each indicator is normalised against fixed
bounds held in `tools/R/bounds.json`, so 60 means the same exposure in every row and in every
round. The bounds come from running this model over two extreme allocations — every hexagon
nature (the floor) and every hexagon agropark (the ceiling) — so the scale is anchored to what
this model can actually produce on this base raster, not to an arbitrary constant.

This changed on 2026-08-07. Scores used to be normalised over each round's own surface, and
under that scheme the rows were NOT comparable, `all-nature` returned NaN by dividing by zero,
and the ranking was inverted — all-agropark scored BETTER for human health than
all-extensive-arable, because the only thing that differed was how many cells fell under the
floor. If you are holding an older copy of this sheet, that is what its caveats describe.

**2. What the map shows is a different scale, still.** The published rasters are stretched to
each round's own min and max, so the colour ramp answers "where, within this round?" while the
score answers "how does this round compare?". That split is deliberate and open — see "Should
the published rasters move to the same fixed scale as the scores?" in
docs/verification-status.rst. It does not affect the numbers below.

## Questions worth answering while you read it

These are the things the people who built the harness cannot judge:

1. **Do the five indicators move independently, or together?** This is a *tradeoff* game, so
   the interesting case is a landscape that improves one indicator and worsens another. If
   every column rises and falls as one, there is nothing for a player to trade off, and that
   would be worth knowing before a workshop rather than during one.
2. **Is the direction right?** For each indicator, does the landscape you would expect to score
   worst actually score worst? A sign error would be invisible to every test in this repository.
3. **Is the spread usable?** If every landscape lands within a few points, players will not see
   their choices reflected, whatever the model does internally.
4. **Is 0 right for `all-nature`?** A landscape with no agriculture has no agricultural
   exposure, so every indicator scores 0 — the floor the bounds were derived from. It used to
   return NaN here. 0 is defensible as "no exposure", but whether a player should see the best
   possible landscape scoring zero on every axis is a design question, not a modelling one.
